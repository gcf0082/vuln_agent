## TODO 驱动 + 多任务 + 验证

从根目录 {target_work_dir} 开始，逐层浏览。**必须保证不遗漏任何攻击面**。

### 第一步：建立 TODO 清单

从根目录开始，用 `ls` 逐层查看目录结构（仅看目录名和文件名，不读取文件内容）。

将所有需要检查的目录写入 `{target_work_dir}/.vuln_agent_output/meta/surface-todo.md`：

```markdown
# 暴露面识别 TODO

## 待检查
- [ ] src/main/java/com/acme/controller/
- [ ] src/main/java/com/acme/handler/
- [ ] scripts/
- [ ] cmd/
...

## 跳过（说明原因）
- node_modules/ (第三方库)
- .git/ (版本控制)
- test/ (测试代码)
...
```

**跳过规则**（根据目录名判断，不深入）：
- `node_modules/`、`.git/`、`__pycache__/`、`venv/`、`.venv/`
- `target/`、`build/`、`dist/`、`out/`、`bin/`、`obj/`
- `test/`、`tests/`、`__test__/`、`spec/`、`__tests__/`
- `vendor/`、`third_party/`、`lib/`（仅第三方库时跳过）
- `docs/`、`doc/`、`static/`、`public/`、`assets/`、`images/`、`css/`、`js/`（前端静态资源）
- `config/`、`conf/`、`migration/`、`migrations/`（仅配置时跳过）
- `docker/`、`.docker/`、`helm/`、`k8s/`、`deploy/`、`ci/`、`.github/`

**优先检查目录**：
- `controller/`、`controllers/`、`api/`、`apis/`、`routes/`、`router/`、`endpoint/`
- `handler/`、`handlers/`、`listener/`、`listeners/`、`consumer/`、`consumers/`
- `cmd/`、`cli/`、`command/`、`commands/`、`console/`
- `script/`、`scripts/`、`bin/`（可执行脚本）
- `service/`、`services/`（含业务逻辑的 service）
- `action/`、`actions/`、`task/`、`tasks/`、`job/`、`jobs/`
- `websocket/`、`grpc/`、`graphql/`、`mq/`

### 第二步：多任务派发

将 TODO 清单中的目录分组，每组派发一个子任务并行处理：

- 每个子任务负责一组目录的攻击面识别
- 子任务独立浏览文件 → 推测 → 验证 → 生成 surface 文件
- 子任务数不超过 5 个，高价值目录优先派发
- 每个子任务完成后，更新 `surface-todo.md` 中对应项为 `- [x]`

**文件名模式参考**（帮助推测潜在攻击面）：
- `*Controller.java`、`*Controller.py`、`*Controller.ts`、`*Controller.go`
- `*Handler.java`、`*Handler.py`、`*Handler.ts`
- `*Route.ts`、`*Route.py`、`*Route.go`
- `*Servlet.java`、`*Filter.java`、`*Interceptor.java`
- `*Service.java`（如果含入口方法）
- `main.go`、`main.py`、`app.js`、`index.ts`、`cli.py`、`cmd.go`
- `*.sh`、`*.bat`、`*.ps1`（可执行脚本）
- `*Application.java`（Spring Boot 启动类，排除）

### 第三步：验证

所有子任务完成后，执行验证：

1. **TODO 完成检查**：读取 `surface-todo.md`，确认所有 `- [ ]` 都已变成 `- [x]`。如有未完成的，补充处理。

2. **文件名模式检查**：遍历已生成的 surface 文件，对照项目中的文件名模式，检查是否有明显遗漏（如某个 `*Controller.java` 没有被识别）。

3. **写入验证报告**：将验证结果写入 `{target_work_dir}/.vuln_agent_output/meta/surface-verify.md`：

```markdown
# 暴露面识别验证

## TODO 完成情况
- 总计：X 项
- 已完成：Y 项
- 未完成：Z 项（列出并补充处理）

## 文件名模式检查
- *Controller.java: 发现 N 个，已识别 M 个
- *Handler.py: 发现 N 个，已识别 M 个
...

## 结论
- [ ] 全部完成，无遗漏
- [ ] 有遗漏（已补充处理）
```

4. **如有遗漏，立即补充处理**，直到全部完成。

## 识别范围

收集所有攻击面（接口 + 非接口）：

- **接口**：REST API、外部 MQ 消费者、gRPC、WebSocket / SSE — 识别 REST API 暴露面时可使用 `rest-api-extractor` skill 辅助分析
- **非接口**：独立可执行脚本、独立工具（含 main 入口的可执行程序）、接收外部输入的任务/消息处理、CLI 命令入口

每条目必须提取精确的**来源信息**（完整文件路径:行号、函数名），路径必须是完整的绝对或相对项目根路径，供后续分析步骤直接使用。**REST 接口必须找到实际的 Controller 入口代码位置（文件路径:行号:函数名），而非路由配置或接口文档来源。****"独立工具"**指有 main 函数作为入口的可独立执行的程序，不是编译产物分析也不是工具类/工具函数。

基于入口处已采集的信息，完整填写输出格式中各字段（代码路径、函数名、接口参数等），尽量详细。不要求主动获取更多信息或跨函数追踪。

识别过程中如果看到值得注意的关键信息（如涉及高危操作、参数来源是用户输入等），可以在对应条目的 `**发现**` 字段中客观记录，但**限于入口处的直接可见信息**。

**识别排除项**：
- Spring Boot `@SpringBootApplication` main 入口类不计为攻击面（仅框架启动入口，无业务逻辑）
- 纯工具类/工具函数不计为攻击面（无独立入口）
- 内部定时任务不计为攻击面（不接收外部输入，无用户可控数据入口）
- 内部 Filter/Interceptor/Service 不计为攻击面（被 Controller 调用，非独立入口）
- 内部 Event Bus / 领域事件监听器不计为攻击面（仅系统内部发布，无外部数据入口）

## 输出格式

⚠️ **每条攻击面条目必须独占一个文件，严禁一个文件包含多个攻击面。**
如有多个攻击面必须拆分为 N 个独立文件分别写入。

每发现一个攻击面，在 {target_work_dir}/.vuln_agent_output/discovered_surfaces/ 下创建一个文件，命名规则：

```
{target_work_dir}/.vuln_agent_output/discovered_surfaces/{type}-{category}-{slug}.md
```

- `{type}` = `iface`（接口）或 `noniface`（非接口）
- `{category}` = REST / MQ / SCRIPT / TOOL / CRON / CLI 等
- `{slug}` = 简短英文标识，小写字母+连字符

文件内容格式包含**通用字段**和**按分类的补充字段**：

通用字段（所有类型必填）：

```markdown
# 攻击面条目

- **类型**：iface（或 noniface）
- **分类**：REST（或 SCRIPT 等）
- **来源**：/src/main/java/com/acme/UserController.java:48 list()
- **描述**：查询用户列表
- **发现**：（可选）识别过程中看到的值得注意的信息，如涉及高危操作
```

按分类的补充字段（根据实际类型选填对应的字段集）：

| 分类 | 补充字段 |
|------|---------|
| REST | `**URL**`：`GET /api/users/{id}`、`**入口**`：`src/main/java/com/acme/UserController.java:48 listUsers()`、`**参数**`：path: id, query: page |
| MQ | `**队列/Topic**`：order.created、`**消费者**`：OrderHandler.onCreated() |
| gRPC | `**服务**`：UserService、`**方法**`：GetUser、`**Proto**`：user.proto |
| WebSocket | `**端点**`：/ws/chat、`**处理器**`：ChatHandler |
| GraphQL | `**类型**`：Query/Mutation、`**字段**`：users、`**Resolver**`：UserResolver |
| SCRIPT | `**脚本名**`：backup.sh、`**语言**`：bash、`**入口**`：/opt/scripts/backup.sh |
| TOOL | `**工具名**`：agent、`**语言**`：Go、`**入口**`：/opt/app/cmd/agent/main.go:15 main() |
| CRON | `**表达式**`：`*/5 * * * *`、`**命令**`：/opt/app/healthcheck.sh、`**文件**`：/etc/cron.d/healthcheck |
| CLI | `**命令名**`：agent、`**入口**`：/opt/app/cli/main.go:8 main() |

补充字段如实填写，没有的信息不写，不要编造。

`slug` 为文件名去掉 `.md` 后缀，如 `REST-api-users-list.md` 的 slug 为 `REST-api-users-list`。

**如未发现任何攻击面，不得在 discovered_surfaces/ 下创建任何文件。**
