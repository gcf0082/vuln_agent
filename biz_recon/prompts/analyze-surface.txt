## 分析方法

**描述事实，不做评判。**"代码做了/没做某项检查"属于事实陈述（**应当报告**，包括"未做"）；"这是否构成风险/漏洞"等属于评判（**仍禁止**）。禁用"风险/漏洞/不安全/可能被攻击"等结论性词。

**未能定位必须显式标注**：在产物里点名"未在工作区找到 X"，并加入末尾的 `## 未能追溯的引用` 节集中列出。**不得编造、不得遗漏、不得静默忽略**。

**文件操作目标路径必报**：文件 I/O / 命令执行 / 网络 / SQL / 加解密 节点必须写出目标本身——文件路径 / 完整命令行 / URL / 表名等，**禁止只写"写入文件 / 执行脚本 / 调用网关"等抽象表述**。动态片段用 `{变量名}` 标注并指明来源。

**代码引用 / 路径 / URL / 命令一律原样保留**——不论长度都不省略、不截断、不用 `...` / `…`。表格列宽不够就让单元格 wrap，流程图节点写不下用 `<br/>`。

**硬编码绝对路径处理**：绝对路径不直接访问，按后缀在工区找候选：
1. 拆后缀序列（长→短）：`/opt/myapp/scripts/scan.sh` → `myapp/scripts/scan.sh` / `scripts/scan.sh` / `scan.sh`
2. 逐个搜索，取最长命中；全未命中 → 进 `## 未能追溯的引用`

**变量值常量化**：常量来源（`static final` / `const` / 字面量赋值 / `@Value` 默认值 / 配置文件 / 枚举）代入字面量；运行时输入（HTTP 字段 / DB / 文件 / 环境变量 / 外部配置）保留 `{var}`。

**关键控制点**——每个场景**必须**描述做了什么校验、没做什么校验，缺一必报：
- 文件上传：后缀/MIME 白名单？大小上限？路径规范化（防 `../`）？
- 文件读取：路径含用户输入？规范化？
- 外部命令：参数含用户输入？命令白名单？
- HTTP 外呼：TLS 校验？主机名校验？目标 URL 含用户输入？
- SQL：参数化绑定（`#{}` / `?`）vs 字符串拼接（`${}` / `+ input`）
- 加解密 / 签名：算法？密钥来源？

**流程图**：用 mermaid flowchart TD 绘制，节点包含具体路径/命令/配置位置。首选嵌入流程图节点——判断类用 `{...}` 菱形节点 + 边标条件分支。观测优先级标记（**不是风险结论**）：
- **🔴 高**：涉及高危操作且操作目标拼接了外部用户输入
- **🟡 低**：涉及高危操作但不含外部用户输入
- 非观测点节点一律不加 emoji

**节点描述中必须给出拼接后的完整字符串**，标注变量来源：
- SQL：`SELECT * FROM users WHERE id = '{body.id}'`，标注拼接点
- 路径：`/data/uploads/{body.filename}`，标注 body.filename 来自请求参数
- 命令：`bash scripts/scan.sh {body.filename}`，标注拼接点

**捕获请求维度**：path / query / 关键 header（鉴权、Content-Type）/ body 字段树。

**入参流向**：追每个请求参数是否流入路径 / 命令 / URL / 写文件 / SQL。**必须沿调用链逐层追踪**，不能停在当前层下结论。只追到外部 SDK / 三方库边界为止。
