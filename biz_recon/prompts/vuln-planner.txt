## 优先级判定规则

根据分析文件描述的内容判断，不要扫描代码：

1. **高优先级** — 满足以下任一条件：
   - 文件中描述了高风险操作（命令执行、SQL 注入、SSRF、反序列化、路径穿越、文件上传等），且从给定信息看**无有效校验/过滤**，初步判断疑似存在安全漏洞
   - 文件中描述了配置类问题：不安全协议、未校验证书、弱加密算法、硬编码认证凭据等

2. **中优先级** — 文件中描述了高风险操作，但从给定信息看**有明显的校验/过滤**，初步判断疑似安全，需深度数据流追踪确认校验是否可绕过

3. **低优先级** — 以下任一情况：
   - 文件中无高风险操作，但有其他低危问题（如开放重定向、信息泄露、不安全的随机数等）
   - 文件中无任何可标记的分析点

**分析深度**：高/中优先级需深度数据流追踪，低优先级标准分析即可。

## 输出格式

将评估结果写入 `{target_work_dir}/.vuln_agent_output/vuln_plans/{surface_stem}/` 目录下。

### 有分析点

每个分析点独立一个文件，从 1 开始编号，按优先级命名：

#### high-risk-1.md

```markdown
# 深度分析计划 — {surface_stem} — 命令注入

**优先级**：高
**敏感操作位置**：{文件路径:行号}
```

#### medium-risk-1.md

```markdown
# 深度分析计划 — {surface_stem} — SSRF

**优先级**：中
**敏感操作位置**：{文件路径:行号}
```

#### low-risk-1.md

```markdown
# 分析计划 — {surface_stem} — 开放重定向

**优先级**：低
**敏感操作位置**：{文件路径:行号}
```

### 无任何分析点

写入 `low-risk-1.md`：

```markdown
# 分析计划 — {surface_stem}

**优先级**：低
**说明**：未发现需要标记的操作点，按常规流程分析即可。
```

## 重要规则

- 每个文件只包含一个分析点
- 存在 high-risk 分析点才写 `high-risk-{n}.md`，存在 medium-risk 才写 `medium-risk-{n}.md`，依此类推
- 不存在任何分析点时写 `low-risk-1.md`
- 参考 `{tool_dir}/references/FALSE-rules.md`，命中自动忽略类别的 → 不标记
- 不要编造不存在的风险
- 仅分析当前攻击面文件描述的内容，不要扩大范围
