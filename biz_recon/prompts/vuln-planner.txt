## 优先级判定规则

根据分析文件描述的内容判断，不要扫描代码：

1. **高优先级** — 满足以下任一条件：
   - 文件中描述了高风险操作（命令执行、SQL 注入、SSRF、路径穿越、文件上传等），且从给定信息看**无有效校验/过滤**，初步判断疑似存在安全漏洞
   - 文件中描述了配置类问题：不安全协议、未校验证书、弱加密算法、硬编码认证凭据等
   - 匹配 `{tool_dir}/references/vuln_rules_index.md` 中的模式

2. **中优先级** — 文件中描述了高风险操作，但从给定信息看**有明显的校验/过滤**，初步判断疑似安全，需深度数据流追踪确认校验是否可绕过

3. **低优先级** — 文件中无高风险操作，但有其他低危问题（如开放重定向、信息泄露、不安全的随机数等）

**通用未知漏洞分析（兜底）**：仅当不存在任何分析点（高/中/低）时，生成一个 low-risk 任务进行通用未知漏洞分析，避免遗漏。若已有任何分析点，则不再添加此任务。

**分析深度**：高/中优先级需深度数据流追踪，低优先级标准分析即可。

## 输出格式

将评估结果写入 `{target_work_dir}/.vuln_agent_output/vuln_plans/{surface_stem}/` 目录下。

### 有分析点

每个分析点独立一个文件，从 1 开始编号，按优先级命名：

#### high-risk-1.md

```markdown
# 深度分析计划 — {surface_stem} — 命令注入

**优先级**：高
**敏感操作位置**：{文件路径:行号}
```

#### medium-risk-1.md

```markdown
# 深度分析计划 — {surface_stem} — SSRF

**优先级**：中
**敏感操作位置**：{文件路径:行号}
```

#### low-risk-1.md

```markdown
# 分析计划 — {surface_stem} — 开放重定向

**优先级**：低
**敏感操作位置**：{文件路径:行号}
```

### 无任何分析点

仅当不存在任何分析点（高/中/低）时，写入 `low-risk-1.md`，进行通用未知漏洞分析：

```markdown
# 分析计划 — {surface_stem} — 通用未知漏洞分析

**优先级**：低
**任务**：对该攻击面的所有外部输入参数，追踪其到敏感操作的完整数据流，检查是否存在安全漏洞。
```

**仅当业务代码特别简单**（如仅几行代码、无实质业务逻辑）时，写入 `none-risk-1.md`：

```markdown
# 分析计划 — {surface_stem}

**结果**：无需分析
**说明**：业务代码特别简单，无分析价值。
```

## 重要规则

- 每个文件只包含一个分析点
- 存在 high-risk 分析点才写 `high-risk-{n}.md`，存在 medium-risk 才写 `medium-risk-{n}.md`，依此类推
- 仅当不存在任何分析点时写 `low-risk-1.md`（通用未知漏洞分析）；若已有任何分析点则不再添加此任务
- 仅当业务代码特别简单时写 `none-risk-1.md`
- 参考 `{tool_dir}/references/vuln_rules_index.md`，匹配对应模式的 → 高优先级
- 不要编造不存在的风险
- 仅分析当前攻击面文件描述的内容，不要扩大范围
