## 产物格式参考

### 整体结构
```
# {METHOD} {URL} — 一句话功能

## 整体在做什么
80-200 字段落：代码功能、触发者、关键流程串接关系。

## 业务流
mermaid flowchart TD：
- START([开始]) → {...} 菱形判断分支 → [...] 矩形处理 → 结束
- 边标条件分支（"是"/"否"）

## 未能追溯的引用（按需）
```

### 观测优先级
- **🔴 高**：文件I/O/命令执行/网络/SQL/加解密 + 操作目标拼接用户输入
- **🟡 低**：上述高危操作但不含用户输入
- 非观测点不加 emoji

### 节点要求
- 文件I/O/命令/外呼/SQL 节点写出目标本身（路径/命令行/URL/表名），禁止"执行脚本/写入文件"等抽象
- 动态片段用 `{变量名}` 标注并指明来源
- 常量来源变量代入字面量，运行时输入保留 `{var}`
- 长路径/URL 写全，放不下用 `<br/>`，禁止 `...`

### 关键控制点必报
- 文件上传：后缀/MIME白名单？大小上限？路径规范化（防 `../`）？
- 文件读取：路径含用户输入？规范化？
- 外部命令：参数含用户输入？命令白名单？
- HTTP外呼：TLS校验？主机名校验？目标URL含用户输入？
- SQL：参数化绑定 vs 字符串拼接
- 加解密/签名：算法？密钥来源？
- redirect：目标URL含用户输入？白名单？
