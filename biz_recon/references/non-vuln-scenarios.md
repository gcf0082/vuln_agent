### 非漏洞场景

- **敏感信息认定**：只有**认证凭据**（密码、Token、密钥、证书私钥）、**电话号码**、**邮箱地址**视为敏感信息。除此以外的信息（如用户名、昵称、ID、地址、非私钥的证书字段等）不认定为敏感信息，不得因此报告漏洞。
- **资源标识作存在性判断或查询后返回**：用户提供的资源标识（如 ID、编号）用来做存在性判断或查询，查询不到就返回，不会走到注入类操作路径的，这种不认为是漏洞。
- **局部模块缺少认证鉴权**：分析的只是一个模块或子系统而非完整独立系统，接口缺少认证鉴权不一定是漏洞——认证鉴权可能在网关、过滤器、拦截器、框架层统一处理。除非分析对象是完整的独立系统（含 Web 服务启动、完整认证流程），否则认证鉴权缺失一般不认为是漏洞。

### 业务逻辑漏洞识别规则

以下区分哪些是真正的业务逻辑漏洞，哪些是正常设计：

**应标记为漏洞**：
- **水平越权**：接口使用用户可控的资源 ID（如 `{userId}`）直接查询/修改数据，且无证据表明服务端绑定了当前用户身份（如从 Token/Session 中取当前用户 ID 并与之比对）→ 标记为漏洞
- **垂直越权**：敏感接口无 `@PreAuthorize`、角色校验或等效鉴权，且分析对象是完整独立系统 → 标记为漏洞
- **流程绕过**：关键步骤状态由前端参数控制（如 `step=3`、`paid=true`），且服务端未做状态校验 → 标记为漏洞
- **竞争条件**：关键资源操作（扣减库存/余额/积分）无锁或非原子操作 → 标记为漏洞
- **重放攻击**：关键操作（支付/领券/下单）无幂等性校验 → 标记为漏洞

**不应标记为漏洞**：
- 接口中使用资源 ID 但仅用于存在性判断或查询后返回到非敏感上下文（如查询用户名是否存在），不涉及越权
- 分步操作的中间步骤参数被包含在请求中但服务端实际未使用该参数做状态判断（死参数）
- 前端隐藏按钮/菜单项在后端无对应接口（仅前端控制展示，后端根本无此功能）
- 使用 `@PathVariable` 注入 ID 但已通过 Spring Security `@PostFilter` / `@PreAuthorize` 等方式做了身份绑定（需确认存在此类注解且配置正确）
